| `proot-02-crash-log.patch` | this project, adapted from the same steamclienttermux patch (`src/tracee/event.c` part) / 이 프로젝트, 같은 steamclienttermux 패치의 `src/tracee/event.c` 부분을 맞춤 | With `PROOT_CRASH_LOG` set, prints the signal, fault address, registers, the mapping of `ip`/`lr` and the command line of a crashing guest program to stderr. `PROOT_CRASH_LOG`가 있으면 죽은 게스트 프로그램의 시그널, 오류 주소, 레지스터, `ip`/`lr`이 속한 매핑, 명령줄을 stderr로 출력 |
| `proot-03-syscall-stat.patch` | this project / 이 프로젝트 | With `PROOT_SYSSTAT=<seconds>` set, counts every system call PRoot stops for per program name and syscall and prints one `PROOT_STAT` line of the busiest pairs to stderr every `<seconds>` (diagnosis of PRoot's own CPU use). A second `PROOT_STAT 경로` line lists the busiest program + call + guest path (digits folded to `#`). `PROOT_SYSSTAT=<초>`가 있으면 PRoot가 멈춰 처리하는 시스템 호출을 프로그램 이름·호출별로 세어 `<초>`마다 가장 많은 짝을 `PROOT_STAT` 한 줄로 stderr에 씀(PRoot 자체 CPU 사용 진단). 둘째 줄 `PROOT_STAT 경로`는 프로그램 + 호출 + 게스트 경로(숫자는 `#`) 상위를 보여 줌 |
| `proot-04-ioctl-filter.patch` | this project / 이 프로젝트 | The seccomp filter sends `ioctl` to PRoot only for the requests PRoot rewrites (SIOCGIFINDEX, FICLONE, terminal TC*2/TCSAFLUSH forms); GPU, sound, input and other ioctls run without stopping PRoot. `PROOT_FULL_IOCTL` set restores tracing every ioctl. seccomp 필터가 PRoot가 고쳐 쓰는 요청(SIOCGIFINDEX, FICLONE, 터미널 TC*2/TCSAFLUSH 형태)만 PRoot로 보냄. GPU·소리·입력 등 나머지 ioctl은 PRoot를 멈추지 않고 실행됨. `PROOT_FULL_IOCTL`이 있으면 예전처럼 모든 ioctl을 추적함 |
| `proot-05-recv-send-filter.patch` | this project / 이 프로젝트 | Netlink sockets PRoot watches (fake or real NETLINK_ROUTE) are moved to descriptors 900-963 right after `socket()` (dup3 + close, close-on-exec kept). The seccomp filter then sends `recvmsg`/`recvfrom` to PRoot only for that range, and `sendto` only for that range or when a destination address is given (Unix socket path translation). Other socket traffic (web helper, X server) runs without stopping PRoot. `PROOT_FULL_RECV` set restores tracing all of them. PRoot가 지켜보는 netlink 소켓(가짜 또는 실제 NETLINK_ROUTE)을 `socket()` 직후 디스크립터 900~963으로 옮김(dup3 + close, close-on-exec 유지). seccomp 필터는 `recvmsg`/`recvfrom`을 그 구간에서만, `sendto`는 그 구간이거나 목적지 주소가 있을 때(유닉스 소켓 경로 변환)만 PRoot로 보냄. 나머지 소켓 통신(웹 도우미, X 서버)은 PRoot를 멈추지 않음. `PROOT_FULL_RECV`가 있으면 예전처럼 전부 추적함 |
| `proot-06-stop-stat.patch` | this project / 이 프로젝트 | With `PROOT_SYSSTAT` set, one more `PROOT_STAT 정지` line per summary: every tracee stop PRoot handles by kind (syscall-exit stops, seccomp, SIGSYS, process events, signals, exits) and the busiest signals per program, because PRoot's CPU use did not follow the syscall stop count alone. `PROOT_SYSSTAT`이 있으면 요약마다 `PROOT_STAT 정지` 줄을 더 씀: PRoot가 처리하는 모든 tracee 정지를 종류별로(시스템 호출 끝 정지, seccomp, SIGSYS, 프로세스 사건, 시그널, 끝남), 프로그램별 가장 많은 시그널. PRoot CPU 사용이 시스템 호출 정지 수만으로는 설명되지 않았기 때문 |
| `proot-07-close-kind-stat.patch` | this project / 이 프로젝트 | With `PROOT_SYSSTAT` set, `close` calls are counted in the `PROOT_STAT 경로` line by what the descriptor is (host-side `/proc/<pid>/fd` link read before the close: `pipe:[#]`, `socket:[#]`, `anon_inode:[sync_file]`, `/dev/kgsl-3d0`, a file path, `(no fd)` for an invalid one). Why: in the Xwayland test the display programs' `close` calls stopped PRoot about 4,000 times a second (PRoot about 28 %); whether `close` can leave the seccomp filter (as `ioctl`/`recv` did) depends on what is closed (pipes need PRoot's pipe shadow). `PROOT_SYSSTAT`이 있으면 `close` 호출을 디스크립터 종류별로 `PROOT_STAT 경로` 줄에 셈(닫기 전에 호스트 쪽 `/proc/<pid>/fd` 링크를 읽음: `pipe:[#]`, `socket:[#]`, `anon_inode:[sync_file]`, `/dev/kgsl-3d0`, 파일 경로, 잘못된 번호는 `(no fd)`). 이유: Xwayland 시험에서 화면 프로그램들의 `close`가 PRoot를 초당 약 4,000번 멈춤(PRoot 약 28%). `close`를 `ioctl`/`recv`처럼 seccomp 필터에서 뺄 수 있는지는 무엇을 닫는지에 달림(pipe는 PRoot의 pipe shadow가 필요) |
| `proot-08-life-events.patch` | this project / 이 프로젝트 | With `PROOT_SYSSTAT` set: each exec is remembered (pid, time) and its exit prints `PROOT_EV 끝 <program> pid N 시작 +Ts 생존 Ds`; the `PROOT_STAT 정지` line adds programs started/ended in the span. Threads (no exec) and fork-only children are not reported. Why: the app's 2 s process list missed short helpers and the exact moments the Steam web helpers start and end (2026-10-30). `PROOT_SYSSTAT`이 있으면 exec를 기억하고(pid, 시각) 끝날 때 `PROOT_EV 끝 <프로그램> pid N 시작 +T초 생존 D초`를 씀. `PROOT_STAT 정지` 줄에 구간 동안 시작·끝난 프로그램 수 추가. 스레드(exec 없음)와 fork만 한 자식은 나오지 않음. 이유: 앱의 2초 프로세스 목록은 짧은 도우미와 Steam 웹 도우미가 생기고 끝나는 정확한 시점을 놓쳤음(2026-10-30) |
| `lsfg-01-present-results.patch` | this project (applied to lsfg-vk by `tools/build-lsfg.sh`, MIT like lsfg-vk) / 이 프로젝트(`tools/build-lsfg.sh`가 lsfg-vk에 적용, lsfg-vk와 같은 MIT) | Frame generation presents with its own `VkPresentInfoKHR`, so the game's `pResults` were never written; vkd3d-proton reads an uninitialised value there and recreated its swapchain every few frames (1,241 times in about a minute, flicker). The patch writes the present result into `pResults`. 프레임 생성이 자체 `VkPresentInfoKHR`로 present해서 게임의 `pResults`가 쓰이지 않았고, vkd3d-proton이 초기화하지 않은 값을 읽어 몇 프레임마다 swapchain을 다시 만들었음(약 1분에 1,241번, 깜빡임). 패치는 present 결과를 `pResults`에 씀 |
